# movie-vfi — 10× temporal reconstruction of fast-recorded 4K footage

Footage shot on a Blackmagic PYXIS 6K was recorded so that real motion plays about 10× too fast
(25 fps container, ~2.5 genuine samples of real motion per second). This project rebuilds normal-speed motion at
25 fps by synthesising 9 frames between each pair of genuine frames, and compares five state-of-the-art video
frame interpolation (VFI) models on the same 16-bit 4K TIFF sequence.

Everything runs through Slurm on a GPU cluster (one H100 NVL 94 GB, one A100 80 GB, driver 545 / CUDA ≤ 12.3).

**Not in this repository:** the footage, all generated frames and previews, model weights, and conda environments.
Upstream model code is referenced as git submodules at the exact commits used (`src/`), never copied.

## Results (shot `test01`: 41 frames of 3840×2160 16-bit Gen 5 log → 401 frames, 1.64 s → 16.04 s at 25 fps)

| Rank | Model | Detail kept in generated frames | Grain kept | Pulse ratio (1.0 = none) | Time (4K, 401 frames) | Weights licence |
|---|---|---|---|---|---|---|
| 1 | BiM-VFI (CVPR 2025) | 61 % | 72 % | 0.98 | 9 min (A100) | research / education only |
| 2 | VTinker (AAAI 2026) | 56 % | 75 % | 1.17 | 16 min (A100) | contradictory (MIT on HF, non-commercial on GitHub) |
| 3 | LDF-VFI (CVPR 2026) | 40 % | 61 % | 1.32 | 4.5 h (H100) | Apache-2.0 |
| 4 | GIMM-VFI (NeurIPS 2024) | 11 % | 32 % | 1.38 | 3 min (A100) | non-commercial (S-Lab 1.0) |
| 5 | EMA-VFI `ours_t` (CVPR 2023) | 1 % | 7 % | 2.16 | 8 min (A100) | Apache-2.0 |

- *Detail / grain kept*: Laplacian variance and high-frequency energy of generated frames relative to the genuine
  frames (centre crop, letterbox excluded). On grainy night footage this is dominated by grain retention.
- *Pulse ratio*: frame-to-frame change next to a genuine frame vs. between two generated frames; a value well
  above 1 means sharp genuine frames alternate visibly with softer generated ones (a 2.5 Hz pulse).
- Log vs. technical Rec.709 input made little difference for any model, so log input (which keeps grading
  latitude) is preferred. Full tables: `results/test01/pulse_metrics.md`, `results/test01/summary.md`.
- These metrics measure detail retention, not whether the synthesised motion is correct; the models disagree
  visibly on positions at t = 0.5. `scripts/eval_holdout.py` implements the objective check (drop every second
  genuine frame, predict it, score against the real one).
- Known artefact: every model leaks picture into the letterbox bars of generated frames (BiM-VFI most visibly);
  `scripts/restore_bars.py` forces the matte rows back to black without touching picture area.

## Frame indexing (all models)

N input frames, factor s → **(N−1)·s + 1** output frames. Output k is genuine input k/s when k mod s = 0
(written with the **original pixels, bit-exact**), otherwise generated at t = (k mod s)/s between inputs ⌊k/s⌋
and ⌊k/s⌋+1. `frame_map.csv` in every run records this per frame.

## Precision: where the 16 bits go

| Stage | LDF-VFI upstream | This pipeline |
|---|---|---|
| Loader | video → torchcodec RGB24 uint8; image folder → PIL `convert("RGB")` uint8; TIFF not accepted | tifffile uint16 → float32 |
| Normalisation | `.to(bf16).div(127.5).sub(1)`: cast before division, so values ≥ 128/255 snap to 8-bit levels | same in `bf16` mode; exact with `--vae_dtype fp32` |
| VAE | hard-coded bfloat16, output `clamp(−1, 1)` | bf16 (default) or float32 |
| Output | `.add(1).mul(127.5).clip(0,255).byte()` inside the sampler (truncates) → H.264 yuv420p | float kept, rounded once to uint16 TIFF |
| Genuine frames | regenerated by the VAE decoder | original pixels pasted back |

bfloat16 has 7 fraction bits, so LDF-VFI's path carries roughly 8–9 bits in highlights. Its 16-bit TIFFs are 16-bit
*containers* of ~9-bit model output, not 16 bits of recovered information. The pairwise flow models (EMA-VFI,
BiM-VFI, GIMM-VFI, VTinker) warp the real 16-bit pixels in float32 end to end.

`scripts/verify_patch.py` proves the float-output LDF-VFI sampler is bit-identical to upstream apart from the final
8-bit step (80 demo frames; `results/ldf_patch_equivalence.json`). No files in `src/` are modified.

## Layout

```
scripts/                 all pipeline code
  ldf_tiff_infer.py      LDF-VFI on 16-bit TIFFs (float sampler built from upstream by counted patches)
  vfi_harness.py         model-agnostic 16-bit harness for pairwise models (adapter contract in its docstring)
  adapters/              EMA-VFI, BiM-VFI, GIMM-VFI, VTinker adapters
  envs/                  per-model env build, smoke-test and run scripts (Slurm)
  inspect_input.py       sequence validation: numbering, gaps, bit depth, alpha, duplicates, possible cuts
  make_rec709.py, colorxf.py   technical Gen 5 log → Rec.709 (Test B), no look, no tone curve
  make_previews.py, compare_models.py, analyze_pulse.py, crop_strip.py   viewing aids and metrics
  eval_holdout.py        objective held-out-frame scoring in a common display space
  restore_bars.py        letterbox matte restoration for generated frames
  run_shot_all.sh        submits the whole per-shot pipeline as dependent Slurm jobs
  status.sh, gpu_now.sh, tail_current.sh   monitoring (light enough for a login node)
  package_delivery.sh, pack_previews.sh   download packaging
src/                     upstream model repos as submodules, pinned to the commits used
config.example.sh        site settings template (copy to config.local.sh, which is git-ignored)
provenance/              package freezes, model checksums, upstream commits, cluster inspection, model vetting
results/test01/          metrics, per-run reports and frame maps (no imagery)
```

## Running a shot

```bash
cp config.example.sh config.local.sh     # set your Slurm account, conda location, login host
source config.local.sh                   # sbatch reads SBATCH_ACCOUNT from the environment
git submodule update --init              # fetch the five upstream model repos at the pinned commits

# one-time setup, submitted from the project root (job logs go to logs/)
sbatch scripts/build_env.sbatch && sbatch scripts/download_models.sbatch    # LDF-VFI env + weights
sbatch scripts/fixup_env.sbatch                                             # after build_env finishes
for m in emavfi bimvfi gimmvfi vtinker; do sbatch scripts/envs/build_$m.sbatch; done

# per shot: put numbered 16-bit RGB TIFFs in input/<shot>/
scripts/run_shot_all.sh test01 all       # prep → 4 pairwise models (log + Rec.709) → LDF-VFI → previews → comparison
scripts/status.sh                        # progress, GPU, finished runs (light enough for a login node)
```

Frames go in `input/<shot>/` (numbered 16-bit RGB TIFFs); results appear in `output/<shot>/<model>/<variant>/`.
Submit jobs from the project root: their logs go to `logs/` relative to it, and `SBATCH_ACCOUNT` from
`config.local.sh` sets the Slurm account. Partition names (`gpu`, `standard`) and GPU types (`A100`, `H100`) in the
`#SBATCH` headers match the cluster described in `provenance/cluster_summary.md`; adjust them for another cluster.

Environments: `scripts/build_env.sbatch` + `scripts/fixup_env.sbatch` (LDF-VFI: Python 3.11.9, torch 2.5.1+cu124,
upstream pins) and `scripts/envs/build_<model>.sbatch`. Weights: `scripts/download_models.sbatch` (LDF-VFI, pinned
Hugging Face revision + sha256) and the per-model build scripts.

LDF-VFI at 4K needs `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`: without it the concat window hit CUDA OOM on
the A100 through allocator fragmentation (43 GiB allocated, 75.8 GiB held).
